# Week 08 — Course Management Navigation Demo

**Advanced Mobile Programming · Lecture 08: Navigation and Routing**

An independent, multi-screen Flutter homework project built from the Week 8 homework slide (PDF page 67). It includes real Drawer navigation, three course tabs, typed push/pop results, a named route, and a simulated login using route replacement. The interface uses fictional sample academic data and runs entirely offline.

## Run the project

Requires Flutter 3.27+ (and Dart 3.4+), Android Studio + an Android emulator **or** Chrome. Run commands from this folder:

```bash
flutter pub get
flutter analyze
flutter test
flutter run -d chrome             # or flutter run -d <device-id>
```

`android/` and `web/` contain hand-provided platform source scaffolding. Native files such as the **Gradle wrapper JAR**, Flutter-generated build settings, and local machine paths are generated by your installed SDK. **On a fresh extraction, run this once before the commands above to complete the platform scaffolding**:

```bash
flutter create --platforms=android,web --project-name week_08_course_management_navigation_demo .
```

Your Flutter SDK will generate any missing native files without replacing the project-specific `lib/` Dart source. Never commit `android/local.properties` or generated caches.

## Test the homework requirements manually

1. Tap **Enter demo workspace**. It uses `Navigator.pushReplacementNamed('/workspace')`; device Back does not return to the entry screen.
2. Open the **Drawer** with the menu icon and switch between **Home**, **Courses**, **Profile**, and **Settings**.
3. On **Courses**, switch between **All courses**, **In progress**, and **Completed**. These are `TabBar`/`TabBarView` selections, not nested routes.
4. Tap a course. `Navigator.push` with a `MaterialPageRoute` passes the course object, showing **title, code, credits**, instructor and description.
5. Toggle **Favorite** and/or **Mark as completed**, then tap **Save changes & return**. The detail route uses `Navigator.pop(CourseUpdate(...))`; the course list and profile summary update from the returned value.
6. Open **Settings → About this project**. This uses the named route `'/about'`. Back returns to Settings.
7. In **Settings**, tap **Exit demo workspace** to clear the route stack and return to the simulated entry screen via `pushNamedAndRemoveUntil`.

## Navigation and state design

- The login screen is **simulated**, not real authentication. The button exists only to demonstrate route replacement. No passwords or services are involved.
- The Drawer swaps sections using a parent `IndexedStack`; switching sections does not push a route.
- Three course tabs remain nested only within the Courses section because the lecture explicitly requests them.
- `CourseDetailsScreen` is a separate pushed page. It receives a typed `Course` and returns a typed `CourseUpdate`.
- `CourseStore` is a simple in-memory `ChangeNotifier`, not a database. Edits reset when the app fully restarts.
- The `'/about'` path is a named route; its Back action pops the route.
- Exit clears prior navigation so Back cannot reveal the old workspace.
